# DesignTokens, as used in [gnorium.com](https://gnorium.com)

Design tokens for Swift web development, with a color palette generated by rule rather than picked by hand.

## Overview

DesignTokens provides CSS custom property definitions and Swift constants for consistent, accessible web interfaces. Its chromatic colors are computed from one rule (below); nothing in the palette is a hand-picked hex value.

## Features

- **Rule-generated colors**: twelve hues, evenly spaced in perceived hue, each at one of APCA's published contrast levels with the page (Lc 60, Lc 75 in increased contrast) and the most chroma Display P3 allows there (P3 is the definition; the sRGB value is its clip); an achromatic neutral ramp from the same contrast model.
- **Layered Architecture**: **Source Tokens** (primitives) and **Applied Tokens** (semantic mappings).
- **Light and dark, default and increased contrast**: four schemes, each derived from the same rule.
- **CSS Generation**: functions that generate the CSS custom property definitions.
- **Type-Safe Swift Constants**: design tokens usable in Swift DSL builders with compile-time checking.

## The color rule

Every color is computed; nothing in the palette is a hand-picked value. Contrast is measured with APCA (SAPC/APCA 0.0.98G-4g, computed exactly in `NamedColors.APCA`), which models dark-on-light and light-on-dark separately. Where the published Lc reads 0 (below Lc 10), the unclipped SAPC is used, so pale fills can be spaced and mirrored. WCAG 2 ratios are kept as floors where a standard binds.

Each palette is built on white (light) and **mirrored to dark by equal APCA**: a dark step is the color with the same APCA contrast against black that the light step has against white. There are four schemes: light, dark, and each with increased contrast (`prefers-contrast: more`).

### The neutral ramp

The ramp is achromatic grays (`NamedColors.Neutral`, `neutralRamp`, emitted by `NeutralTokensCSS`). Values are 8-bit sRGB.

1. **Fills.** There are five steps, evenly spaced in APCA from the page. A step is a third of the APCA of the 3:1 gray laid at `opacity-low` over white, which makes that gray fill 3. Fills don't change with increased contrast.
2. **Base border.** This is 3:1 against the page, as WCAG 2.x 1.4.11 asks of a control's outline.
3. **Text.** Each text step is set in light by a standard:
   - disabled text at 3.96:1 (exempt by WCAG, kept below placeholder)
   - placeholder at 4.5:1 against the page and against fill 3 (WCAG 1.4.3)
   - subtle text at APCA Lc 75
   - base text at 18.12:1
4. **Subtle border.** This sits midway in APCA between fill 5 and the base border.
5. **One construction for every scheme.** Each text step keeps its fraction of the APCA distance from the base border to the APCA maximum. The same rule lays out light, dark and both increased-contrast schemes.

### Increased contrast

Increased contrast raises the foreground only. The base border moves to the APCA of 7:1 on white, the named colors' 3:1 → 7:1 expressed in APCA. Every text step keeps its fraction of the way from the border to the APCA maximum. The fills stay, so text on them gains contrast. In dark, the steps above the border are compressed toward white (218 to 251), as the rule gives.

### Named colors

There are twelve hues, 30° apart in OKLCH starting at pure red's hue (`#FF0000`, h ≈ 29.23°): red, orange, yellow, lime, green, mint, cyan, blue, indigo, violet, magenta, pink. Gray is the achromatic thirteenth.

Each color is a Display P3 color: its hue kept, the most chroma P3 allows, at the lightness where its APCA contrast with the page, measured with APCA's Display P3 luminance, is one of APCA's own published levels. P3 is the definition (user, 2026-10-14). The sRGB value is not solved for its Lc: it is the P3 color's clip, the CSS fallback, overridden by the P3 value under `@media (color-gamut: p3)`.
- **Default: Lc 60**, APCA's minimum for short labels and captions (content text that is not body text: about 24px regular or 16px bold). This level covers links and syntax.
- **Increased contrast: Lc 75**, APCA's minimum for body text.
- **Polarity:** light is dark-on-white; dark is light-on-black, using APCA's reverse-polarity formula.

**The sRGB clip.** On an sRGB screen the browser clips each P3 color: its linear sRGB channels clipped to [0, 1], then encoded (relative-colorimetric clipping, as Chrome and Safari do). That clip (`NamedColors.clipHex`) is the sRGB value everywhere: the CSS tokens' default, theme-color, the web manifest, emails, `favicon.ico`, social images. By the user's decision its contrast drifts from the level, as the table shows: Lc 56–64 by default, Lc 72–79 in increased contrast. Gray is achromatic, the same in sRGB and P3.

Each name gives three things:
- **Color:** `--glyph-{name}` / `--color-{name}`. Links (`--color-link`) and syntax colors use these; there is no separate text set.
- **Solid fill:** the same color, `--fill-{name}` / `--background-color-{name}`.
- **Subtle fill:** in the default schemes, the color at 20% over the page (`NamedColors.subtleShare`), mixed in gamma-encoded Display P3 and precomputed (`NamedColors.subtle`): its P3 value as `oklch()`, its sRGB value the clip; no runtime `color-mix`. In the increased-contrast schemes, it is the hue's lightness nearest the color's at which base text reads at 7:1.

Hover and active states mix toward the scheme's extreme in Oklab. Tokens are written as `oklch()`, so transitions interpolate in Oklab.

### Labels on solid fills

A solid fill's label is `--color-on-solid`, the page's own color: white in light and black in dark (`--extreme-inverted`). A white label on a light solid reads at Lc 65 in P3 (62–70 on the sRGB clip), or Lc 80 in increased contrast. A black label on a dark solid reads at Lc 62 in P3 (58–64 on the clip), or Lc 76. `--color-inverted-fixed` stays white for what must always be white (emails, a source document's white text).

### Border roles

Neutral borders are assigned by WCAG 2.x 1.4.11, which asks 3:1 of a boundary needed to identify a component or its state:
- **`borderColorBase` (3:1):** text inputs, textareas, selects and dropdown triggers, search fields, the pager's page boxes, checkboxes, radios, toggles, bordered buttons with no fill, the editor box, a table's resize handle, and graphical objects that carry meaning (relation-graph edges, chart axes).
- **`borderColorSubtle` (the subtle border step):** everything decorative or grouping, where content or another cue identifies it. This covers cards, accordions, tables and their lines, reader frames, dividers and rules, modals and popovers, menus, code blocks, fieldsets, rails, attachment frames, chips with text, and chart grids.

## Architecture

### 1. Source Tokens
Primitives.
- **Named colors**: the twelve hues above, per scheme.
- **Neutral ramp**: five fills, the subtle and base borders, and four text steps, per scheme.
- **Grays**: light and dark grayscale ramps.
- **Syntax colors**: code highlighting by role, drawn from the named colors (`SyntaxTokensCSS`).

### 2. Applied Tokens
Semantic tokens that map source primitives to specific UI roles.
- **Foregrounds**: `colorBase`, `colorSubtle`, `colorEmphasized`.
- **States**: `colorProgressive`, `colorDestructive`, `colorSuccess`, `colorWarning`.
- **Layout**: `spacing`, `size`, `zIndex`, `borderRadius`.
- **Typography**: `fontFamilyBase`, `fontSizeXXXLarge28`, `lineHeightContent`.

## Installation

### Swift Package Manager

Add DesignTokens to your `Package.swift`:

```swift
dependencies: [
    .package(url: "https://github.com/gnorium/design-tokens", branch: "main")
]
```

## Usage

### Generating CSS

```swift
import DesignTokens

// Generate Source and Applied tokens for light mode
let sourceCSS = SourceTokensLightModeLessContrastCSS()
let appliedCSS = AppliedTokensLightModeLessContrastCSS()
```

### Using Tokens in Swift

```swift
import DesignTokens
import HTMLBuilder
import CSSBuilder

div {
    "Hello World"
}
.style {
    color(colorBase)
    backgroundColor(backgroundColorProgressive)
    padding(spacing16)
    fontSize(fontSizeMedium16)
}
```

## Requirements

- Swift 6.2+
- Depends on `web-builders` for CSS generation
